# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
# 再灌「超时权威样例」→ 站规页看超时权威与已钉开腿超时界
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿（落地即钉死超时界） |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 + 超时界钉界贯验 |

## 配对超时策略（乙口径·全局唯一）

超时权威是多源配置兼容问题，全局只贯彻一种口径——**乙·以线路级超时表钉界为准**：

- **开腿落地即钉界**：装载写开腿时按进站站所属线路读 `线路超时` 表钉秒，缺省回落站规
  `最大行程秒`；`线路键/超时秒/超时界/超时权威` 随开腿行同一 INSERT 物化——写开腿与钉界同成败。
- **扫描只读钉界**：缺腿超时扫描只读开腿行已钉的 `超时界`，禁止改用全局值覆盖已钉线路界；
  判定与旁路写闸同一事务同票，`在途→已旁路` 条件更新保证并发扫描/复扫**不一腿双判**。
- **改权威不回改**：改站规秒/线路秒只影响此后新钉的开腿；扫描中途改权威不半旁路
  （扫描不读配置），写事务经写闸串行。
- **对照甲口径**（仅以站规全局秒钉界）：同刻进站的两腿共享同一全局界、命运必然相同；
  乙口径下线1短界腿与线2长界腿可不同命运。

接口：

| 接口 | 作用 |
| --- | --- |
| `GET /api/超时权威` | 超时权威只读接口：开腿键、线路、钉死秒、权威来源、timeout_at、valid |
| `POST /api/站规` | 站规写闸（`最大行程秒` 须正整数），只影响此后新钉开腿 |
| `GET /api/线路超时` | 各线超时权威：钉线秒或回落站规 |
| `POST /api/线路超时` | 线路超时写闸：正整数钉线秒；空/非正删行回落站规 |
| `POST /api/超时扫描` | 超时扫描旁路写闸：只读已钉界，判定与旁路写闸同票 |

夹具「**超时权威样例**」：线1 钉 1800（线路超时表）、线2 无行回落站规 7200；
卡21/卡22 同刻 08:00 进站，卡23 09:00 进站推水位到 09:00——只过线1短界。
乙：仅卡21（短线腿）旁路，卡22/卡23 在途；甲（仅全局秒）：两腿同命运——两口径可区分。

测试：`cd backend && python -m pytest`（乙口径区分、复扫不双判、钉界同成败、并发不半旁路、贯验抓撕裂）。
